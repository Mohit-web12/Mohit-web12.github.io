Agentic financial workflow

Statusin progress The design is done. The build is next.
ToolsPython (boto3, pandas, jsonschema), Amazon Bedrock, S3, IAM, CloudWatch
ModelMeta Llama 3.1 8B Instruct, through the Converse API

The question

Can a language model handle the fuzzy part of personal finance, deciding what each transaction is, while plain code handles everything that has to be exact? I'm building a small pipeline on AWS to find out. I'm doing all of it myself: the prompts, the data schema and validation, the AWS setup, the KPIs, and the write up.

What I've done so far

Phase one is the design. A Python script reads a CSV of transactions from S3 and runs five stages in order. Only three of them call the model.

  • The model never does math. Observe computes total spend, total income, the top three merchants and the average expense in pandas, so those numbers come out exact.
  • Every answer gets checked. Act has to return JSON that matches a schema and puts each transaction in one of five categories: Shopping, Dining, Utilities, Income or Other. If it doesn't, the script asks again.
  • Cheap and predictable. I picked Llama 3.1 8B because it costs less per token, and run it at temperature 0 with JSON only output.
  • Least privilege. One IAM role can invoke the model and read and write objects in the project bucket, nothing else. CloudWatch keeps the run logs.

What I'd do next

  • Write the orchestrator and run it end to end on a small CSV.
  • Label a sample of transactions by hand and measure how often the model agrees with me.
  • Track tokens and cost per run.
  • Compare it against the merchant rules in SpendGauge, which are free and instant, to see whether the model is worth it.
